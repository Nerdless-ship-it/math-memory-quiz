# 速算与常识训练

一个无需安装、零依赖、零构建的网页记忆训练应用。所有科目共用一套答题引擎，
数据存在浏览器本地（localStorage），可直接作为纯静态站点托管。

## 科目

**速算**

| 科目 | 题量 | 内容 |
|---|---|---|
| 百分数与分数 | 30 | 百分数 ↔ 分数双向换算 |
| 平方与幂次 | 24 | 平方数、立方数、四次幂双向记忆 |

**考公常识**

| 科目 | 内容 |
|---|---|
| 天干地支 | 天干地支的阴阳五行、十二时辰 |
| 十二生肖 | 生肖与地支对应、排序 |
| 二十四节气 | 节气与顺序编号、节气含义 |
| 历史朝代 | 朝代与开国君主、都城 |
| 化学元素 | 元素、符号、原子序数 |
| 历史常识 | 著作、典故、事件、人物 |
| 法律常识 | 宪法、国家机构、民法、刑法要点 |
| 时政常识 | 稳定制度性事实（⚠️ 有时效标注） |

**图形推理**

| 科目 | 内容 |
|---|---|
| 正方体展开图 | 28 题。题干给展开图，四个选项是折叠后的立体图，选出能由它折成的那一个 |
| 立方体截面图 | 24 题。题干给一个被平面所截的立方体，选出截面**不可能**是的那一项 |

> 图形题的**所有图形都由几何算法生成内联 SVG**，没有外链图片、没有手写坐标。
> 好处是几何必然自洽：立方体的 11 种合法展开图、三组对面关系、截面边数（只可能是 3~6 边）
> 全部由算法判定；干扰项也带**可复述的几何错误**（例如选项里有两个面在展开图上是相对面，
> 而相对面在立方体上永远不可能同时可见）。
>
> 一处刻意的设计：截面图里「不可能」的那个选项渲染成一个**七边形**。因为立方体只有 6 个面、
> 截面最多 6 边，七边形正是真题最常见的陷阱选项；它外观与正常选项一致，不会「把答案画出来」。
> （早期版本把这种选项画成写着「不成立」的方框，等于直接把答案标出来，已修掉。）

**动画演示**：交卷后的错题订正里，图形题会多一个按钮：

- **正方体展开图 → 演示折叠过程**：从摊平的展开图连续折成立方体，面上标着 1~6 号可对照。
- **立方体截面图 → 演示切割过程**：平面扫过立方体，实时画出每一层的截面多边形——
  直观展示「同一个立方体，不同深度切出三角形 / 四边形 / 五边形 / 六边形」。

动画默认**不预加载**（点按钮才加载），且尊重系统的 `prefers-reduced-motion`
（开启时直接显示终态，不做动效）。折叠动画的两端由 `net-fold.js` 的折叠结果保证正确：
t=0 与展开图逐格一致，t=1 与折叠结果逐面一致（有单测把关）。

> ⚠️ **关于时政常识**：这一科的内容有时效性，卡片上会显示「更新于 YYYY-MM-DD」。
> 看到日期偏旧时请以最新官方表述为准。
>
> ⚠️ **关于法律常识与时政常识的准确性**：这两科由 AI 生成，虽已尽力核实，
> 仍可能存在事实错误。**请以权威法条与官方文件为准**，并欢迎用「数据导入 / 导出」
> 功能修正内容。

## 训练机制

- **双向随机出题**：每对关联随机问正向或反向，两个方向数量均衡，每轮完整覆盖全部条目。
- **两种作答模式**：
  - **考公常识 8 科一律选择题**：四选一，干扰项从同科目同维度抽取以保证难度同构，
    且**选项顺序每轮随机**（正确答案不固定落在某一项）。
  - **速算 2 科为填空题**：直接回忆，不受选择题逻辑影响。
  - 科目在 `registry.js` 的 `questionTypes` 里声明支持哪些模式，这是唯一真相源。
- **单题掌握度**：按「题」而非按「卷」记录熟练度，五级制。
- **间隔重复**：熟练度越高，下次复习间隔越长（10 分钟 → 1 天 → 3 天 → 7 天 → 21 天）。
- **错题集与错题重练**：答错的题自动归集，可针对错题单独开一轮；连续答对 2 次自动移出。
- **连续打卡**：跨日完成测试累计连续天数。
- **中途存档**：刷新或误关页面后，未完成的测试可继续（题型与已选项一并恢复）。
- **数据导入导出**：备份 / 恢复本地数据，也可用来批量修正题库内容。

## 本地运行

```powershell
npm start
```

打开 `http://127.0.0.1:4173`。

## 测试

```powershell
npm test                     # 单元测试（题库质量、存储、引擎、掌握度、注册表）
npm run test:browser         # 百分数与分数端到端（真实浏览器，冻结用例）
npm run test:powers-browser  # 平方与幂次端到端（真实浏览器，冻结用例）
npm run test:all-subjects    # 全部 10 个科目端到端 + 首页看板 + 响应式溢出检查
```

`test:browser` 与 `test:powers-browser` 是升级前就存在的**冻结用例**，断言 DOM 行为与
页面文案完全不变；它们保持全绿是本项目重构正确性的证明，因此**不要修改它们**。

浏览器测试默认使用 Windows 上的 Edge，可用 `EDGE_PATH` 环境变量覆盖。

> `test/` 下只有 `*.test.mjs` 会被 `npm test` 自动纳入；
> `all-subjects-smoke.mjs` 是端到端脚本，需要先 `npm start` 起服务，需单独运行。

## 已知限制

- **法律常识与时政常识由 AI 生成**，虽已尽力联网核实并在数据中标注来源与不确定条目，
  仍可能有事实错误。请以权威法条与官方文件为准，并欢迎用「导出 / 导入」修正内容。
- **时政常识有时效性**，卡片上标注了「更新于 YYYY-MM-DD」，日期偏旧时请以最新官方表述为准。
- **十二生肖 / 二十四节气 / 历史朝代三科目前只有正向题**。原因是这些科目的多个维度
  互有同名交叉（同一段文字既是某题的题目、又是另一题的答案），反向出题会产生
  「秦 → ？」这类有多个正确答案的无解题。要恢复双向需为这些科目补写语义明确的反向条目，
  详见 `docs/ARCHITECTURE.md` 第 3.0.1 节。


## 部署

`public` 是完整的静态网站文件夹，入口是 `public/index.html`。
**不要只上传 `index.html`**，它需要同目录的 CSS、图标以及 `public/js`、`public/subjects` 下的脚本。

### 线上站点

| 站点 | 地址 | 触发方式 |
| --- | --- | --- |
| Cloudflare Pages（主站） | <https://math-memory-quiz.pages.dev/> | GitHub App 连接本仓库，推送到 `main` 自动构建 |
| GitHub Pages | <https://nerdless-ship-it.github.io/math-memory-quiz/> | `.github/workflows/deploy-pages.yml`：推送后先跑 `npm test`，通过再发布 |

### Cloudflare Pages

Cloudflare 侧是 Pages 项目 `math-memory-quiz`，已用 GitHub App 连到本仓库：

- 生产分支 `main`，推送到 `main` 自动构建
- **构建命令与输出目录都留空 → 部署的就是仓库根目录**。所以根目录的 `index.html`
  （跳转到 `./public/`）是必需的，不要删；应用本体在 `/public/` 下，真正的应用地址是
  <https://math-memory-quiz.pages.dev/public/>

⚠️ 已知现象：**用合并提交（merge commit）推送时，Pages 这次构建可能被记成推送前的提交**，
表现为「GitHub 上已经更新、Cloudflare 还是旧内容」。判断方法是看该次部署的 Source 提交
是不是你刚推的那个；遇到时再推一个普通提交即可刷新，或用下面的手动上传。

### Cloudflare Workers（另一条可选路径）

`wrangler.jsonc` 已把 `./public` 配成静态资源，用 Workers Builds 连接本仓库时：

- 根目录保持仓库根目录（留空或 `/`）
- 部署命令填 `npm run deploy:cloudflare`
- 不需要填构建输出目录，`wrangler.jsonc` 已指定 `./public`

部署前可先自检：

```powershell
npm run check:cloudflare
```

### 直接上传

选择整个 `public` 文件夹；该文件夹打开后第一层就能看到 `index.html`。

## 架构

新增科目是**数据操作，不是编码操作**：加一个 `public/subjects/<id>.item.js`
数据文件，再在 `public/js/registry.js` 的 `SUBJECTS` 里加一条即可，
不需要新增任何页面与控制器代码。

详细的接口契约（数据 schema、引擎 API、存储 v2、迁移规则、验收标准）见
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。**开发前请先读它。**

```
public/
├── index.html              首页：科目网格 + 数据看板 + 历史成绩 + 错题集
├── quiz.html               通用科目答题页（?subject=<id>，支持 ?mode=mistakes）
├── percent.html            百分数与分数（数学科目专用页）
├── powers.html             平方与幂次（数学科目专用页）
├── js/
│   ├── engine.js           通用答题引擎（所有科目共用，含填空与选择题两种题型）
│   ├── registry.js         科目注册表 —— 「有哪些科目」的唯一真相源
│   ├── storage.js          存储层 v2（记录 / 掌握度 / 错题 / 存档 / 打卡）
│   ├── mastery.js          掌握度与间隔重复调度
│   ├── distractors.js      选择题干扰项生成
│   ├── adapters/           科目适配器（判题、题面渲染）
│   └── subjects-page.js    首页渲染
└── subjects/               考公常识题库（纯数据）
```

**架构不变量有测试守着**（`test/architecture.test.mjs`）：渲染/控制代码里出现硬编码的
科目 id、或 `index.html` 手写科目卡片，都会让 `npm test` 变红。所以「新增科目零新增代码」
不是口头约定，而是被强制执行的约束。
